# 8단계 — 게임 로직 최종본

팀 갈래말래 · 갈래? 말래? · 김하민(2271046) · 2026-11-24

게임 규칙을 순수 Java로 완성한 폴더이다. Swing 화면·TCP 소켓·JSON 메시지·실제 서버 타이머는 포함하지 않는다. 기존 `G.S.G-integration` 폴더는 수정하지 않았다. UI·서버 코드는 나중에 전달받은 뒤 별도로 연결한다.

## 현재 진행 상황

**게임 로직 8/8단계 완료. 남은 로직 단계 0개. UI·서버 연동과 실제 2인 네트워크 검사는 별도 후속 작업이다.**

| 단계 | 내용 | 새 핵심 클래스 |
| --- | --- | --- |
| 1~4 | 카드·분배·판 상태·선결정·총통·일반 턴 | 기존 클래스 보존 |
| 5 | 피 이동 우선순위, 흔들기·폭탄 조건, 뻑 보상 | `SpecialRules` |
| 6 | 광·띠·열끗·피·족보·국진 점수 | `ScoreCalculator` |
| 7 | 고 재선택, 박·배율, 고정 정산, 보유금 상한 | `GoStopRules` |
| 8 | 위 규칙을 한 판으로 연결하고 준비·종료·다음 판 관리 | `MatchEngine`, `RoomRules` |

5~7단계 폴더는 각 규칙 부품을 독립적으로 공부·검사하는 누적본이다. 서비스패부터 정산까지 한 판 전체를 실행할 때는 **이 8단계 폴더만** 사용한다. 모든 단계의 같은 패키지를 한 모듈 소스 루트에 동시에 넣으면 중복 클래스 오류가 난다.

## IntelliJ에서 실행

1. IntelliJ의 **파일 → 열기**에서 이 폴더의 `pom.xml`을 선택하고 **프로젝트로 열기**를 선택한다. 기존 Game Logic 창과 별도 창으로 열면 설정이 섞이지 않는다.
2. 프로젝트 SDK에 설치된 JDK를 지정한다. Java 8 문법으로 작성했으며 실제 검사는 JDK 21에서 했다. 사용 중인 JDK 26으로도 실행 가능하도록 최신 문법·외부 라이브러리를 사용하지 않았다. JDK 26에서의 실측 검증 여부는 `검증기록.md`를 확인한다.
3. 가져오기가 끝나면 `src/main/java`와 `src/test/java`가 각각 소스·테스트 루트가 된다. Maven 프로젝트로 인식하지 못한 경우 우클릭 → **Maven 프로젝트로 추가**한다.
4. `src/test/java/gallaemallae/game/FullGameCheck.java`를 열고 `main` 옆 초록색 실행 버튼을 누른다.
5. 마지막에 `PASS: 최종 게임 로직 ... 무작위 완주 2000판`이 나오면 전체 로직 검사가 통과한 것이다. `GameRulesCheck`는 예전 1~4단계의 회귀 검사이다.

테스트는 JUnit이 아닌 실행형 `main`이다. `mvn test`만 실행하는 것으로 전체 검사 프로그램이 실행되지는 않는다. 위의 main 실행이나 아래 스크립트를 사용한다.

PowerShell에서 실행하려면 다음과 같이 한다. `JDK설치폴더`는 `bin`의 상위 폴더이다.

```powershell
powershell -ExecutionPolicy Bypass -File .\run-checks.ps1 -JdkHome "JDK설치폴더"
```

## 직접 패를 내보는 로직 실습

`src/main/java/gallaemallae/game/LogicConsole.java`의 `main`을 실행한다. 두 사람의 차례를 한 콘솔에서 번갈아 입력하며 동작을 확인한다. UI·서버 연결 실습이 아니다.

| 상태 | 입력 예시 |
| --- | --- |
| 일반 제출 | `PLAY 17` — 출력된 손패 ID 사용 |
| 서비스패 | `SERVICE 49` 또는 `SERVICE 50` |
| 흔들기와 제출 | `SHAKE 17` — 해당 월 3장, 바닥 0장 |
| 폭탄 | `BOMB 17` — 해당 월 3장, 바닥 1장 |
| 폭탄 기회 사용 | `DECK_ONLY` |
| 같은 월 2장 중 선택 | `SELECT 18` — 출력된 후보 ID 사용 |
| 국진 | `GUKJIN_PI` 또는 `GUKJIN_ANIMAL` |
| 고·스톱 | `GO` 또는 `STOP` |
| 실습 종료 | `QUIT` |

콘솔 실습은 가상 시각을 사용해 생각하는 동안 기권되지 않는다. 30초 경계 자체는 자동 검사에서 검증한다. `QUIT`은 실습 프로그램만 끝낸다. 실제 게임 중 퇴장은 `RoomRules.leave()`로 처리한다.

## 게임 시작 메서드와 호출 순서

**4단계의 시작 메서드:** `RoundInitializer.start(Seat dealer, Random random)`.

**최종본의 외부 시작 진입점:** `RoomRules.ready(Seat seat, long nowMillis)`.

```java
RoomRules room = new RoomRules(new Random());
room.join(Seat.FIRST, 1_000_000L);
room.join(Seat.SECOND, 1_000_000L);
room.ready(Seat.FIRST, nowMillis);
room.ready(Seat.SECOND, nowMillis);
// 새 대결이면 DEALER_SELECTION. 각자의 selectionCandidates()에서 패를 골라 제출한다.
room.chooseDealer(Seat.FIRST, room.selectionDraw(), firstCardId, nowMillis);
room.chooseDealer(Seat.SECOND, room.selectionDraw(), secondCardId, nowMillis);
// RESELECT면 남은 4장 중 재선택, REDRAW면 두 사람 모두 새 선택.
// 선이 결정되면 내부 startRound()가 분배·총통 검사·MatchEngine 생성을 수행한다.
```

이 예시는 호출 순서를 설명한다. `nowMillis`, 패 ID, 플레이어 식별은 나중에 서버가 공급해야 하며 이 문서에 실제 통신 구현은 없다.

| 메서드 | 역할 |
| --- | --- |
| `RoomRules.join()` | 계정 잔액을 유지해 입장 |
| `ready()` / `cancelReady()` | 준비·분배 전 취소 |
| `chooseDealer()` | 서버 접수 순서대로 선결정 |
| `act()` | 판 번호·버전·행동·카드 ID 제출 |
| `viewFor()` | 자기 손패와 공개 정보의 불변 복사본 조회 |
| `expire()` | 전달받은 시각으로 선택 시간 초과 판정 |
| `leave()` | 분배 전 무료 퇴장 / 분배 후 기권 |
| `MatchEngine.submit()` | 한 판의 순수 규칙 처리 |

## 처리 이유와 규칙 상호작용

- **서비스패:** 손에서 사용하면 획득·상대 획득피 이동·더미 1장 손 보충 후 같은 차례를 계속한다. 보충 서비스패는 자동으로 소비하지 않는다. 더미를 뒤집다가 나온 서비스패는 획득 후 정상 월 패가 나올 때까지 뒤집는다.
- **같은 월 2장:** 손패 대상 선택을 마치기 전 더미를 공개하지 않는다. 선택 대기도 하나의 상태이므로 UI가 없어도 검사할 수 있다.
- **뻑:** 바닥 묶음의 생성자와 누적 발생 횟수를 별도 보관한다. 자뻑 2장/상대 뻑 1장과 쓸은 더하며, 3뻑은 즉시 고정 정산한다.
- **폭탄:** 흔들기 횟수를 자동 증가시키지 않는다. 기회 2회씩 누적하고 다음 자기 차례부터 1회씩 선택 사용한다. 기회 턴은 새 뻑·쪽·따닥을 만들지 않는다.
- **점수:** 획득과 피 이동을 마친 뒤 계산한다. 띠 장수와 단, 열끗 장수와 고도리는 각각 합산하며, 12월 띠는 초단에서 제외한다.
- **국진:** 판 전체에 전환 상태를 한 번만 기록한다. 전환 국진을 빼앗아도 같은 판에서는 쌍피 분류가 유지된다. 쌍피로 점수를 만들 수 있을 때 고·스톱 전에 묻는다.
- **고:** 고 선언 당시 기본 점수를 저장한다. 고 보너스를 제외한 기본 점수가 1점 이상 증가해야 다시 묻는다. 전체 행동이 소진된 마지막 턴에 조건을 충족하면 자동 정상 정산하고, 조건을 만들지 못하면 나가리다.
- **2026-11-24 추가 확정 — 잔여 서비스패:** 양쪽 손패와 폭탄 기회가 모두 소진되었는데 더미 맨 아래에 서비스패만 남았다면 획득·피 이동 없이 현재 점수로 종료한다. 일반 월 패가 남은 채 행동이 소진되는 것은 실제 분배 완주 검사에서 오류로 확인한다.
- **정산:** 승자 측 고·역고·흔들기·폭탄과 나가리, 네 가지 박을 독립 계산한다. `BigInteger`로 금액·배율을 계산한 뒤 양쪽 잔액 상한을 적용한다. 배율이 금액 상한 때문에 잘려도 계산 근거를 남긴다.
- **판 종료:** 승부 종료와 잔액 반영을 한 경로로 처리해 중복 정산을 막는다. 나가리는 누적·기존 선 유지, 동시 총통 무효는 누적 유지, 확정 승부는 누적 초기화이다.
- **2026-11-24 추가 확정:** 패 분배 전에는 선결정 중 퇴장·시간 초과도 무료 퇴장이다. 분배 후에만 10만원 기권 정산을 적용한다. 기권자는 퇴장, 승자는 방에서 새 상대를 기다린다. 일반 정산 파산은 방을 닫아 양쪽을 내보낸다.
- **잘못된 행동:** 상태 복사본에서 검증하므로 실패한 요청은 패·버전·마감 시각을 바꾸지 않는다. 같은 판의 요청은 직렬 처리하며, 마감 시각 도달 자체는 요청의 유효성과 무관하게 시간 초과를 일으킨다.

## 추후 UI·서버 연결 시 지켜야 할 계약

1. 클라이언트의 Seat·시각·잔액을 신뢰하지 않고 서버가 확정한다. 시각은 서버의 단조 증가 시계 기준 밀리초로 통일한다.
2. 각 방의 `RoomRules`를 서버가 하나씩 소유한다. 판 번호·버전을 요청에 붙이고 거절되면 최신 뷰를 전달한다.
3. `viewFor(요청자)`만 보내며 다른 사람의 뷰나 내부 객체 전체를 직렬화하지 않는다. `View`에는 더미 원본과 상대 손패 목록이 없다.
4. 실제 예약 작업에서 `expire(nowMillis)`를 호출한다. 로직 객체 자체는 타이머를 만들지 않는다. 유효한 후속 선택 요청마다 새 30초이며, 잘못된 행동은 연장하지 않는다.
5. 통신 끊김은 `leave()`로 알려주고 정산 결과를 계정 저장소에 한 번만 반영한다. 다음 판에는 다시 두 사람 준비가 필요하다.
6. 실제 화면·통신·동시 입력·네트워크 지연 검사는 아직 하지 않았다. 자동 2,000판 검사는 Java 로직 검사이다.

동일한 마감 시각의 두 선결정이 한 번의 만료 검사에서 함께 걸리면 현재 구현은 좌석 순서 FIRST→SECOND로 먼저 만료자를 고른다. 이는 승패 규칙이 아닌 처리 순서이며, 선결정 중 무료 퇴장에는 정산이 없다. 이 순서나 UI 표시 방법은 실제 서버 연동 시 재검토할 수 있다.
